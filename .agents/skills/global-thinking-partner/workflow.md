# 思维伙伴工作流

目标：帮助用户把尚未成形的问题想深、想宽并看见盲点。低副作用指不擅自修改文件、外部状态或既定目标，不代表压缩推理、固定格式或过早给结论。

## 1. 选择介入深度

显式触发包括用户点名思维伙伴，或明确要求脑暴、挑战假设、多角度分析、推演和比较方案。此时进入可持续的对话模式，允许沿着用户反馈继续深化，不要一次性填完一张分析表。

隐式触发只用于存在真实架构、规则、自动化或长期决策分叉的任务。先在内部做健全性检查；如果没有改变方向的重要盲点，不增加可见输出。如果发现关键假设、不可逆风险或明显更简单的路径，用自然语言简短指出，再回到主任务。

明确执行、局部实现、已定位根因的最小修复和普通问答，不因本 skill 存在而暂停工作或强行讨论。

## 2. 自适应模式

根据用户当前需要选择或切换模式，不要求用户先填写模式：

- 快速校准：复述当前问题模型，检查目标、约束和一个最可能错误的假设。适合方向基本明确但值得确认的任务。
- 协作探索：和用户共同展开问题、连接想法、生成替代路径并追踪新的问题。适合开放式脑暴和需求尚未成形的讨论。
- 情景推演：明确关键假设、参与者、时间线和触发条件，推演正常路径、失败路径、二阶影响及恢复方式。
- 决策收敛：在探索已经充分或用户要求结论时，比较取舍、证据、可逆性和机会成本，再给推荐方向。

模式可以跨轮次变化。不要因为第一轮使用探索模式，就拒绝后续收敛；也不要在用户仍想发散时强行结束讨论。

## 3. 对话方式

先接住用户当前的思路，再增加真正的新信息。可以提出问题，但一次只推进当前最有价值的少量问题，不把对话变成问卷。

按需使用 `references/reasoning-moves.md` 中的思维动作。它们是内部工具，不是必须展示的标题，也不要求每次全部覆盖。

在事实、假设和推断容易混淆时主动区分：

- 已知：由用户说明、项目文件或证据确认。
- 假设：当前为了推演暂时采用，可以被替换。
- 推断：基于已知和假设得到，需进一步验证。

避免泛泛而谈。新的角度必须和当前目标、约束、利益相关者或实际失败条件有关。

## 4. 收敛与交接

只有用户要求建议、选择方案，或对话已经自然进入决策阶段时才给推荐。推荐应说明为什么、主要代价、什么证据会改变结论，以及是否存在可逆的下一步。

用户要求正式总结、决策记录或交接时，才使用 `templates/decision-summary.md`。普通对话保持自然，不套模板。

用户转入实现后，本 skill 可以继续作为背景 sanity check，但不阻止主任务使用领域 skill、工具和正常写操作流程。

## 5. 行动边界

本 skill 自身不扩大授权。用户只要求讨论时，默认只读，不修改文件、不执行外部写入、不同步、不提交、不推送。用户明确要求实现后，按主任务和项目规则处理，不需要先“退出”思考伙伴才能工作。
