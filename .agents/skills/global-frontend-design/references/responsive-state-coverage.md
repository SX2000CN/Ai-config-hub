# 响应式与状态覆盖

设计响应式行为或检查生产 UI 完整性时使用本参考。

## 响应式行为

不要把移动端当成被挤压的桌面端。明确界面如何适配：

- 导航：折叠、堆叠、抽屉、Tabs 或简化操作。
- 内容层级：小屏首屏保留什么。
- 表格：卡片化、横向滚动、列优先级或摘要行。
- 表单：单列、分组、固定操作区、字段帮助位置。
- 仪表盘：卡片顺序、图表简化、指标分组。
- 弹窗：必要时改成全屏 sheet、底部 sheet 或内联面板。

## 断点思维

使用项目已有断点。每个主要布局检查：

- 极窄移动端。
- 常规移动端。
- 平板或分屏宽度。
- 桌面端。
- 需要时检查宽屏桌面。

## 必要状态类别

按需考虑：

- 初始加载。
- 骨架屏或 spinner 行为。
- 空数据。
- 筛选后空数据。
- 数据加载错误。
- 可重试状态。
- 部分数据。
- 保存或提交中。
- 成功确认。
- 校验错误。
- 操作禁用。
- 权限不足。
- 离线或数据过期。
- selected、active、hover、focus。
- 长文本、长列表和异常大的数字。

## 状态设计规则

- 空状态说明发生了什么以及下一步。
- 错误状态提供恢复方式，而不是只展示失败。
- 加载态尽量保持布局稳定，减少跳动。
- 禁用状态应清晰且可解释。
- 长内容应有意识地换行、截断、clamp 或滚动。
