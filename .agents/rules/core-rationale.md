# 规则依据表

本文件不渲染、不分发，只服务维护。用途：规则本身无法察觉自己的理由已经消失。
每条规则在此登记「它防的是哪个具体失败」和「什么条件下复核」。

**复核触发条件是模型发布，不是日历。** 一代模型的缺陷被下一代修好之后，
为旧缺陷写的规则会变成噪声甚至反效果（OpenAI 已确认"检查你的工作"这类指令
在新模型上导致多余测试）。每次模型代次升级后跑一次 `/doctor prompt-audit`，
并对每条做消融判断：删掉它，只有在失败复发时才加回来。

判据三问（不通过就删）：

1. 这条是用一次真实事故换来的吗？
2. 违反它是否不可逆或影响面大？
3. 它在代码或文件系统里看得见吗？

实践戒律：**问模型是否需要某条指令，不是测量**。看行为，不看自述。

---

## 协作方式

- **防的失败**：模型用通用最佳实践覆盖用户的具体现场（"业界通常这么设计"压过"我这里必须这样"）。
- **依据**：Anthropic Field Guide to Fable 指出模型遇到未知项时只能按最佳猜测行动；Guardrails Beat Guidance 实测显示正向指令是单独有害的那一类，因此这里以"不静默覆盖现场"的禁止式为主。
- **复核触发**：出现"按通用做法覆盖现场"的具体案例，或模型代次升级后发现该约束已被内化。
- **状态**：首句是假设（"做出用户会做出的判断"），不是事实；未验证，按待验处理。

## 信息不足时

- **防的失败**：两个方向——过度提问（把决策推回用户）与沉默猜测（做出不是用户要的东西）。HiL-Bench 显示两者被同一指标同时惩罚。
- **依据**：SAGE-Agent 提出问"欠定的参数"而非整个任务；Claude Code 的 plan mode 与 Devin 的置信度门都把闸门挂在"对方案的不确定性"上。
- **复核触发**：用户感觉被问得过多或过少；模型代次升级后提问行为变化。
- **状态**：这条是全套规则里最脆弱的。指令遵循随规则数下降，压缩会静默抹掉约束——它只能靠上下文生效，无法结构化强制。已知弱点，不假装解决。

## 执行环境

- **防的失败**：在 Windows 上用错 shell 语法导致命令报错；后台任务拿不到新刷新的 PATH 导致"命令不存在"。
- **依据**：本机实际踩过的坑（事故换来的，通过三问）。省略会直接导致错误。
- **复核触发**：换机器、换 shell、或 Claude Code 改变工具 shell 行为时。
- **状态**：这是"环境事实"，但属于稳定 gotcha 而非可变状态，故留在常驻层。

## 用户偏好

- **防的失败**：引入同类新方案导致重复造轮子；未验证的结论被当结论交付；文档噪音。
- **依据**：用户多次口头确认过的取舍，代码与对话中推不出来。
- **复核触发**：任一条被触发时复核是否仍然成立；长期未触发的按三问处理。
- **状态**：其中"验证强度按影响面"是自治边界（防过度验证），不是普通偏好。

## 文档与工作状态

- **防的失败**：状态文件膨胀成日志／百科；为一次性问答建任务卡。
- **依据**：CURRENT 卫生规则的历史违反记录（"最近关闭"曾超上限、状态枚举漂移）。
- **复核触发**：CURRENT 再次超限，或状态枚举再次漂移。

## 边界

- **防的失败**：不可逆操作未经确认执行；扩大任务范围；绕过平台约束；凭证落盘或外传。
- **依据**：官方 harness 设计与 Amp 权限模型两处独立印证"边界取决于可逆性"。
- **复核触发**：发生不可逆操作事故时；强制层（hook）上线后，散文部分应降为一行说明。
- **状态**：**强制层上线前，这条只靠上下文生效，是已知弱点。** WP-1 完成后本节应缩短。

## 规则本身

- **防的失败**：规则过期后仍然生效（模型升级不会自动让旧规则失效）；规则与事实冲突时模型迁就规则。
- **依据**：Boris Cherny 的消融方法（删掉全部，只在失败复发时加回）；生成代次审计实践。
- **复核触发**：每次模型代次升级。
- **状态**：本文件本身就是这条规则的执行机制。

## 未采纳但留档的备选

- **把常驻规则降级为 path-scoped / 嵌套文件**：省上下文，但压缩后 path-scoped 规则不会重新注入，而协作契约必须永远成立。故保留在未限定范围的常驻层。
- **全部改成否定式**：实证研究基于编码任务，禁令天然适配代码；"现场优先"这类决策规则改成禁令会失真。可改的改，改不动的登记为假设。
- **用记忆系统替代规则层**：调研的 mem0／Letta／Zep／basic-memory 都不承担"不变式"角色，且会变成第二份规则文件；memory poisoning 已是 OWASP 列名风险。auto-memory 只放事实与偏好，绝不放流程。
- **四工具规则分化**：同一条内容对不同模型家族可能冗余／承重（arXiv 2608.24641）。当前内容是"事实 + 偏好 + 边界"形态而非提示风格，跨模型风险低；只有出现可复现的单工具失灵时才分化，并登记例外。
