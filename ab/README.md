# A/B 跑道：你的配置 vs 裸跑

用途：回答"这套配置到底有没有帮到我"。在跑出结果之前，所有"配置有用"的说法都只是信仰。
个人级、跨项目全局配置**没有任何受控证据**——你正处在无人验证过的地带，所以只能自己测。

## 证伪条件（先定好，再跑）

- **主证伪**：留出集上「配置胜裸跑」的成对胜率 ≤ 55%，或 95% 置信区间跨过 50%，
  任务数 ≥ 30 对。→ 结论：配置没有可测的收益，回到删减。
- **伴随证伪**：任何一条 rubric 断言全程 `held-by-inertia`（从未被触发面覆盖）。
  → 它是死重，删掉，不要庆祝。

## 方法（来自 agentic-benchmark 的方法论，逐条落实）

1. **任务来源**：从你自己的 merged PR / 编辑历史挖 ~30 个真实任务。
   工具可用 [mdarena](https://github.com/HudsonGri/mdarena)（pip，MIT）。
   不要用合成任务——它们测不出你的真实取舍。
2. **两组对照**：`config`（当前完整配置）vs `naked`（空规则、无 skill、无 MCP）。
3. **判分**：
   - 确定性优先：有测试的用真实测试判，不要让模型判能用测试判的东西。
   - **五个字典序轴**：Correctness（门控其余）→ 断言成立率 → 成对胜率 → 效率 → 稳定性。
     **绝不用加权总分**——它会把噪声当信号。
   - 每条二元 rubric 断言配一个 regex 锚点 + `appliesIf` 门槛；触发面没出现在 diff 里的
     断言记 **`held-by-inertia`**，不算通过。
4. **judge 纪律**：
   - judge 模型**固定，且不是你的日常模型**。
   - **只看 diff，绝不看过程**（过程会指纹化你的 harness）。
   - **成对判定 + 随机座次 + 交换顺序复核**；顺序一换结论就翻 → 判平局。
5. **留一组配置永远看不到的判据**（防 rubric 被钻空子——这是实测过的失败模式：
   训练侧 judge 分数涨、真实 judge 到顶后掉）。
6. **留出集**：任务对半分，rubric 只在训练一半上调，报告只看留出一半。

## 目录结构

```
ab/
  tasks/          挖出来的真实任务（每个一个 md：输入 + 预期可判据的产物）
  rubric.json     二元断言 + appliesIf + 留一组（对配置不可见）
  score.mjs       确定性评分器（含 held-by-inertia 判定）
  score.test.mjs  评分器测试
  out/            结果（不跟踪）
```

## 不要做的事

- 不要用"跑一周看看"这种模糊标准替代对照。
- 不要堆 judge 层——实测显示额外评审层会退化；有效的是消除噪声源（顺序、分解）。
- 不要在 rubric 调过之后再看训练集的分数。
