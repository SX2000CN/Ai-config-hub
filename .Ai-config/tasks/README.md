# 工作任务卡

本目录保存当前项目的多任务 AI 协作接手卡。任务卡用于跨会话、跨工具保留当前工作的必要上下文，避免新任务覆盖旧任务状态。

## 什么时候创建任务卡

应创建或更新任务卡：

- 跨模块功能、复杂 bug、配置/流程/文档机制调整，且后续有接手价值。
- 一个任务中途被另一个任务打断，需要保留旧任务现场。
- 工作完成但用户尚未确认，需要保留验证结果和残留风险。
- 当前任务阻塞、暂停、等待验证或需要后续接手。

通常不需要任务卡：

- 简单问答、一次性命令和一轮内完成的小修复。
- 小型文案或格式修正。
- 无代码改动、无后续行动的临时分析。
- 一轮内完成且已验证、没有残留风险的小修复。
- 常规任务如果没有等待确认、验证缺失、残留风险或跨会话价值，也不需要创建任务卡。

## 命名

推荐命名：

```text
YYYY-MM-DD-short-topic.md
```

例如：

```text
2026-05-13-work-state-v2.md
```

## 状态

- `进行中`：当前正在推进。
- `暂停`：任务未完成，但用户切换了焦点或暂时不做。
- `阻塞`：缺信息、权限、外部结果或用户决策。
- `等待验证`：实现或文档已改，但验证未完成。
- `待用户确认`：AI 已完成一轮工作，或无法继续验证，需要用户审核、确认或决定。
- `已关闭`：任务已经无需继续处理，且关闭依据已记录；涉及修改、验证或残留风险时需要用户明确确认。
- `已废弃`：用户或事实表明不再做。
- `已合并`：该任务被另一个任务吸收。

## 关闭规则

- 验证状态记录最小相关验证即可；只有跨管线改动、审计式验证或准备真实同步前，才需要把 `check-all.ps1` 作为默认总检查。
- AI 可以把任务移出“当前活动”，但不能随便标为 `已关闭`。
- 有文件修改、配置修改、脚本执行、同步风险、验证缺失、残留风险或用户尚未审核时，默认状态应是 `待用户确认`。
- 涉及修改、同步风险、验证缺失或残留风险的任务，只有用户明确针对该任务表达“通过了”“没问题”“这个结束”“关闭这个任务”“不用管了”“不做了”等语义时，AI 才可改为 `已关闭` 或 `已废弃`。
- 无法验证时可以进入 `待用户确认`，但必须记录未验证原因、风险和建议验证方式。
- 任务被合并时，旧任务卡记录合并目标，新任务卡反链旧任务。

```markdown

当前活动：是 / 否

## 目标

<任务要达成什么。>

## 背景和当前上下文

<不看历史对话也必须知道的信息。>

## 最近结论

- <当前最重要的判断或结果。>

## 已确认事实

- <用户约束、技术判断或已经核实的事实。>

## 已尝试 / 已排除

- <尝试过什么，为什么不要重复。>

## 当前卡点

<没有则写“暂无”。>

## 验证状态

<未关闭时写“暂无”。>
```
