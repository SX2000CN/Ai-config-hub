# 工作任务卡

本目录保存当前项目的多任务 AI 协作接手卡。任务卡用于跨会话、跨工具保留当前工作的必要上下文，避免新任务覆盖旧任务状态。

## 什么时候创建任务卡

应创建或更新任务卡：

- 非简单功能开发、bug 修复、配置修改、流程调整或文档机制设计。
- 一个任务中途被另一个任务打断，需要保留旧任务现场。
- 工作完成但用户尚未确认，需要保留验证结果和残留风险。
- 当前任务阻塞、暂停、等待验证或需要后续接手。

通常不需要任务卡：

- 简单问答。
- 一次性命令。
- 小型文案或格式修正。
- 无代码改动、无后续行动的临时分析。

## 命名

推荐命名：

```text
YYYY-MM-DD-short-topic.md
```

例如：

```text
2026-05-13-work-state-v2.md
```

## 状态

- `进行中`：当前正在推进。
- `暂停`：任务未完成，但用户切换了焦点或暂时不做。
- `阻塞`：缺信息、权限、外部结果或用户决策。
- `等待验证`：实现或文档已改，但验证未完成。
- `待用户确认`：AI 已完成一轮工作，或无法继续验证，需要用户审核、确认或决定。
- `已关闭`：任务已经无需继续处理，且关闭依据已记录；涉及修改、验证或残留风险时需要用户明确确认。
- `已废弃`：用户或事实表明不再做。
- `已合并`：该任务被另一个任务吸收。

## 关闭规则

- AI 可以把任务移出“当前活动”，但不能随便标为 `已关闭`。
- 有文件修改、配置修改、脚本执行、同步风险、验证缺失、残留风险或用户尚未审核时，默认状态应是 `待用户确认`。
- 涉及修改、同步风险、验证缺失或残留风险的任务，只有用户明确针对该任务表达“通过了”“没问题”“这个结束”“关闭这个任务”“不用管了”“不做了”等语义时，AI 才可改为 `已关闭` 或 `已废弃`。
- 无法验证时可以进入 `待用户确认`，但必须记录未验证原因、风险和建议验证方式。
- 任务被合并时，旧任务卡记录合并目标，新任务卡反链旧任务。

## 任务卡模板

```markdown
# 工作任务：<任务标题>

任务 ID：YYYY-MM-DD-short-topic
创建时间：YYYY-MM-DD HH:mm
更新时间：YYYY-MM-DD HH:mm
状态：进行中 / 暂停 / 阻塞 / 等待验证 / 待用户确认 / 已关闭 / 已废弃 / 已合并
当前活动：是 / 否

## 目标

<任务要达成什么。>

## 背景和当前上下文

<不看历史对话也必须知道的信息。>

## 最近结论

- <当前最重要的判断或结果。>

## 已确认事实

- <用户约束、技术判断或已经核实的事实。>

## 已尝试 / 已排除

- <尝试过什么，为什么不要重复。>

## 当前卡点

<没有则写“暂无”。>

## 下一步最小动作

1. <下一位 AI 应优先做的动作。>

## 验证状态

- <命令或人工验证结果；未验证时说明原因。>

## 残留风险

- <没有则写“无”。>

## 相关文件

- `<path>`：<说明。>

## 不要重复

- <容易重复踩坑的方向；没有则写“暂无”。>

## 关闭依据 / 最终结果

<未关闭时写“暂无”。>
```
