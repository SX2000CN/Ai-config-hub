# 多任务工作状态机制设计方案

本文设计一种按需启用的轻量项目级 AI 协作状态机制，用来让任意 AI 编程工具在中断、隔天继续、切换任务或切换工具时快速恢复现场。

当前状态：v2 已设计，目标是替代早期单槽位 `docs/ai/CURRENT.md` 机制。

## 背景

`ai-config-hub` 已经用全局规则、项目文档、工具专属补充和项目级 skill 中枢解决了大部分长期上下文问题。

剩余缺口是“当前正在做的事”的连续性：

- 功能开发做到一半被中断，几天后继续时需要重新回忆上下文。
- bug 修复长期没有突破，切换另一个 AI 工具时容易重复已经尝试和排除过的方向。
- 做功能 A 时临时插入功能或 bug B，旧状态容易被新状态覆盖。
- AI 当前对话结束并不等于用户审核通过，不能让 AI 自行判断任务完成并丢弃状态。

因此需要一个项目内的工作状态系统，作为给下一位 AI 或下一次会话的接手导航。

## 目标

- 让任意 AI 工具进入项目后，可以先从 `docs/ai/CURRENT.md` 判断当前是否有活动任务、暂停任务、阻塞任务或待确认任务。
- 支持多个任务并存，但同一时间只有一个当前活动任务。
- 让有接手价值的任务拥有独立任务卡，避免新任务覆盖旧任务状态。
- 有接手价值的工作完成一轮后不要求用户每次手动归档；需要用户审核或仍有风险时进入 `待用户确认`，由任务卡保留结果、验证和风险。
- 保持清晰、精简、低噪音，避免成为完整日志、日报或项目管理系统。
- 只依赖普通 Markdown 文件和轻量规则，不把 hook、数据库或脚本状态机作为核心机制。
- 支持渐进启用：小项目可以只有项目规则或 `CURRENT.md`，长期项目再补任务卡、registry 和项目级 skills。

## 非目标

- 不替代 README、架构文档、CHANGELOG、issue、PR 或 git log。
- 不记录完整操作流水、搜索过程或对话全文。
- 不做复杂看板、数据库、JSON 状态机或自动任务调度系统。
- 不默认记录敏感信息、真实凭证、私有 URL 或生产细节。
- 不要求每个小任务、简单问答、一次性命令或马上完成且没有接手价值的改动都创建任务卡。
- 不把 `docs/ai/tasks/`、`archive/` 或 `skills-registry.md` 当作所有项目的强制健康指标。

## 推荐位置

完整形态推荐使用：

```text
docs/ai/
  README.md
  CURRENT.md
  tasks/
    README.md
    YYYY-MM-DD-short-topic.md
  archive/
```

含义：

- `docs/ai/README.md`：AI 配置中枢索引和边界说明。
- `docs/ai/CURRENT.md`：AI 接手入口和工作状态总览。
- `docs/ai/tasks/README.md`：任务卡规则说明。
- `docs/ai/tasks/*.md`：单个任务的无损接手卡。
- `docs/ai/archive/`：可选长期整理目录，不作为每次任务完成的必需动作。

## 核心定义

`docs/ai/CURRENT.md` 是项目当前 AI 协作接手入口和工作状态总览。它不承载完整任务上下文，而是指向对应任务卡，并给出按任务类型读取事实源的导航。

`docs/ai/tasks/*.md` 是任务事实源。任务卡保存目标、背景、状态、最近结论、已确认事实、已尝试和排除方向、卡点、下一步、验证状态、残留风险和相关文件。

日常工作中，“关闭任务”取代“手动归档”。`已关闭` 表示任务已经无需继续处理，且关闭依据已记录；涉及文件修改、配置修改、脚本执行、同步风险、验证缺失或残留风险时，必须先有用户明确确认。未审核、未验证或有残留风险的任务应保持为 `待用户确认`、`等待验证`、`阻塞` 或 `暂停`。

任务卡是接手成本的保险，不是默认文书。简单问答、一次性命令、一轮内完成且无残留风险的小修复，不创建任务卡。

## 接手导航职责

`CURRENT.md` 应在顶部说明新 AI 如何接手当前项目。不同项目的事实源不同，因此接手导航应由项目自己维护。

以本仓库为例：

```text
1. 先读 docs/ai/CURRENT.md，判断是否有当前任务和任务卡。
2. 再按 CURRENT.md 指引读取 docs/ai/README.md，理解 AI 协作中枢边界。
3. 如果任务涉及全局规则，读 rules/shared/core.md、rules/tools/*、templates/*。
4. 如果任务涉及 project-ai-config-hub skill，读 skills/shared/project-ai-config-hub/ 和工具入口源。
5. 如果任务涉及渲染/同步，读 scripts/render*.ps1、check*.ps1、sync*.ps1 和 docs/sync-workflow.md。
6. 需要理解整体数据流时，读 docs/architecture.md。
7. README.md 只作为项目概览补充，不作为强制第一入口。
```

## 任务状态

任务卡使用以下状态：

- `进行中`：当前正在推进。
- `暂停`：任务未完成，但用户切换了焦点或暂时不做。
- `阻塞`：缺信息、权限、外部结果或用户决策。
- `等待验证`：实现或文档已改，但验证未完成。
- `待用户确认`：AI 已完成一轮工作，或无法继续验证，需要用户审核、确认或决定。
- `已关闭`：任务已经无需继续处理，且关闭依据已记录；涉及修改、验证或残留风险时需要用户明确确认。
- `已废弃`：用户或事实表明不再做。
- `已合并`：该任务被另一个任务吸收。

常规流转：

```text
进行中 -> 等待验证 -> 待用户确认 -> 已关闭
进行中 -> 待用户确认
进行中 -> 暂停 -> 进行中
进行中 -> 阻塞 -> 进行中
进行中 -> 已废弃
待用户确认 -> 进行中
待用户确认 -> 已关闭
进行中/暂停 -> 已合并
```

## 关闭和确认规则

- AI 可以自动把任务移出“当前活动”，但不能随便标为 `已关闭`。
- 有文件修改、配置修改、脚本执行、同步风险、验证缺失、残留风险或用户尚未审核时，默认状态应是 `待用户确认`，并记录验证情况和残留风险。
- 涉及修改、同步风险、验证缺失或残留风险的任务，只有用户明确针对该任务表达“通过了”“没问题”“这个结束”“关闭这个任务”“不用管了”“不做了”等语义时，AI 才可改为 `已关闭` 或 `已废弃`。
- 对于无代码改动、无后续行动的简单分析或头脑风暴，默认可以不创建任务卡；如果已经创建任务卡，也应记录关闭依据后再关闭。
- 如果环境缺失或无法验证，不应永久卡在 `等待验证`；可以进入 `待用户确认`，但必须标明未验证原因、风险和建议验证方式。
- 任务被合并时，旧任务卡必须写明合并目标，新任务卡必须反链旧任务。

## 多任务切换规则

### 继续当前任务

当用户说“继续”“按刚才的做”“修你刚才发现的问题”等，应读取 `CURRENT.md` 中的当前活动任务和对应任务卡，继续更新同一个任务。

### 插入新任务

当用户临时插入新任务时：

1. 先把旧活动任务改为 `暂停`、`阻塞`、`等待验证` 或 `待用户确认`。
2. 在旧任务卡写清楚暂停原因和下一步。
3. 新建或切换新任务卡。
4. 更新 `CURRENT.md` 的当前活动任务。

### 同时给多个任务

如果任务强相关，可以建立一个父任务卡并在其中列子任务；如果任务相互独立，应建立多个任务卡，`CURRENT.md` 只指向当前活动任务，其余任务列在暂停、阻塞或待处理区域。

### 完成但未确认

有接手价值的一轮实现、修复或分析完成后，如果用户尚未确认且涉及文件修改、配置修改、同步风险、验证缺失或残留风险，应把任务移入 `待用户确认`，并在任务卡记录结果、验证、残留风险和等待用户审核的下一步。简单问答、一次性命令或一轮内完成且无残留风险的小修复，不需要进入任务卡流程。

## 任务卡必填字段

任务卡应包含：

- 任务 ID、创建时间、更新时间、状态。
- 目标。
- 背景和当前上下文。
- 最近结论。
- 已确认事实。
- 已尝试 / 已排除。
- 当前卡点。
- 下一步最小动作。
- 验证状态。
- 残留风险。
- 相关文件。
- 不要重复做什么。
- 关闭依据或最终结果。

## 与其他机制的边界

- `CURRENT.md` 与 Claude Code Todo 不同：Todo 是单次会话内执行步骤，`CURRENT.md` 和任务卡是跨会话和跨工具的项目接手状态。
- `CURRENT.md` 与 memory 不同：memory 保存长期偏好、背景和非显然项目动机；任务卡保存当前未关闭工作的现场。
- `CURRENT.md` 与 CHANGELOG 不同：CHANGELOG 面向已发布变化，任务卡面向未关闭或刚关闭的工作。
- `CURRENT.md` 与 git log 不同：git log 记录代码历史，任务卡记录接手当前工作的必要上下文。

## project-ai-config-hub 集成要求

`project-ai-config-hub` 分身 skill 应把 v2 作为默认项目级 AI 配置中枢形态，但按项目复杂度分层启用：

- 轻量项目可只创建 `docs/ai/CURRENT.md`，甚至只保留项目规则文件。
- 需要跨会话、多任务或等待确认时，再创建 `docs/ai/tasks/README.md` 和任务卡。
- 只有存在项目级 skill 或用户要求登记时，才创建 `docs/ai/skills-registry.md`。
- `docs/ai/archive/` 只作为长期整理目录，不是日常任务关闭所需结构。
- 旧项目已有 v1 `CURRENT.md` 时不得直接覆盖，应先判断是否明确空闲。
- 不能确认为空闲的 v1 状态，包括 `进行中`、`暂停`、`阻塞`、`等待验证`、`待用户审核` 或 `待用户确认`，都应迁移为 `docs/ai/tasks/YYYY-MM-DD-<topic>.md`，再把 `CURRENT.md` 改为总览并指向任务卡。
- 迁移、覆盖、删除旧状态前应给计划并等待确认。

## 已确认

- `docs/ai/CURRENT.md` 是接手入口和状态总览，不是完整任务事实源。
- `docs/ai/tasks/*.md` 是有接手价值任务的无损接手卡，不是每个任务的必需产物。
- 主 `README.md` 不是 agent 固定接手入口，只作为项目概览补充。
- 日常关闭任务不需要移动到 `archive/`。
- v2 不引入 hook、数据库或复杂脚本状态机。
