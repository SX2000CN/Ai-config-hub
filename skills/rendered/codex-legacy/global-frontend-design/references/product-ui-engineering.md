# 产品级 UI 工程

在已选择视觉方向与旋钮后，用本参考把 **product** 轨道落到可维护、可操作、状态完整的界面。
营销页请主读 [anti-slop.md](anti-slop.md)；本文件仍约束其中的表单、导航与可访问基线。

## 基本关系

- **视觉方向是主张，产品工程是约束。**
- 不要为了复用把主张抹成灰模版；也不要为了「好看」牺牲理解、状态与 a11y。
- 产品默认旋钮偏 **低 VARIANCE / 低 MOTION / 高 DENSITY**；signature 宜落在信息层级、工具感或关键数据时刻，而不是整页装饰动画。

## 信息层级

每个界面都应让这些问题一眼清楚：

- 这个界面是做什么的？
- 用户第一步应该做什么？
- 哪些是主内容、次要内容、元信息？
- 哪些操作安全、次要、危险或不可逆？
- 系统当前处于什么状态？

用尺寸、字重、对比、位置、分组表达优先级。层级承接已选方向，而不是套通用卡片网。

## 布局节奏

保持稳定、可扫描的节奏：

- 页面边距与最大宽度
- 区块间距、卡片/面板内边距
- 控件高度、图标尺寸、行高
- label 与控件间距、标题与正文间距
- 表格/列表行高与对齐列

高密度很好，但必须**有意识且一致**。DENSITY≥7 时：少用层层套卡；用分割线、sticky 表头、紧凑工具条表达结构。

## 组件边界

在当前就有价值时再抽取：

- 重复的视觉结构
- 清晰的领域概念
- 值得隔离的有状态交互
- 不应反复手写的可访问性模式

不要仅因出现两次就抽象；若抽象藏掉关键上下文，先保留直观结构。

## 产品状态（非 happy path）

按需覆盖：

- 无数据、筛选后无结果、部分数据
- 慢加载、失败、可重试；skeleton 形状贴近最终布局
- 校验失败、保存中、成功确认
- 权限不足、不可用原因、危险确认
- 超长文本/数字、极端空值、极小屏

矩阵见 [responsive-state-coverage.md](responsive-state-coverage.md)。

## 文案与可操作性

- 按钮描述具体动作；同一意图全流程同词
- 空状态：为何为空 + 下一步
- 错误：问题 + 恢复方式；不道歉文学、不甩锅用户
- 危险操作写清后果
- 用用户语言，不用 webhook/内部表名等实现词（除非受众就是开发者且界面就是那层）

## 表单与数据控件

- Label 在字段上方（或等价可见关联）；placeholder 不作唯一 label
- 帮助与约束尽量在提交前可见；错误靠近字段
- 主按钮对比度合格；禁用态说明原因
- 长列表/表：排序、筛选、空结果、分页或虚拟滚动按项目已有模式
- 批量与不可逆操作需要确认或撤销路径

## 应用壳与导航

- 导航当前项明确；深度与面包屑符合信息架构
- 桌面与小屏导航模式沿用项目已有（侧栏/顶栏/抽屉）
- 全局噪音（toast、角标、未读）不抢主任务
- 营销式 eyebrow、大 hero、高 VARIANCE 破格：**默认不要**出现在 CRUD/设置主路径

## 与营销区块 hybrid

当产品内嵌营销模块（升级页、空状态品牌插画、onboarding）：

1. 标明分区旋钮：壳层 product，模块可略升 VARIANCE/MOTION
2. 品牌色与圆角仍服从应用 token
3. 模块内可读 anti-slop；退出模块后回到产品密度与状态纪律

## 工程硬约束（hub）

- 最小完整 diff；优先复用组件与 token
- 不新增依赖与平行设计系统，除非用户要求或项目已有
- 密钥、凭证、私有 URL、生产数据不进代码与文档
- 验证见 [verification.md](verification.md)
