# 视觉方向与审美原则

创建、重设计、明显打磨或 review 前端界面时，优先使用本参考。本文件是本 skill 的视觉判断主源。

## 先有观点

强 UI 需要明确的设计立场。不要先问“怎么把组件摆好”，而要先回答：

- 这个界面应该给人什么感觉？
- 用户第一眼应该注意到什么？
- 哪个视觉选择能让它属于这个产品，而不是任何 SaaS 模板？
- 哪个细节会被记住，同时不损害可用性？

如果回答不出来，先做设计 brief，不要直接写代码。

## 选择视觉主题

选择一个符合产品语境的方向，并给它命名：

- 极简、快速、克制。
- 编辑部/内容驱动。
- 高密度企业指挥中心。
- 柔和消费级 SaaS。
- 工业工具感。
- 轻松有趣的引导流程。
- 精致、高级、低噪音。
- 复古未来感。
- 自然、有机、触感。
- 几何/装饰艺术风格。

不要混合太多风格。一个一致的主题胜过一堆装饰效果。

## 避免泛化 AI UI

除非产品语境明确需要，避免：

- 白底紫蓝渐变加圆角卡片的模板感。
- 没有产品理由的居中 hero、三卡片、通用 CTA 组合。
- 随机装饰 blob、无意义光晕和廉价玻璃拟态。
- 所有区块权重相同的平均用力布局。
- 默认 sans 字体、默认圆角、默认阴影堆出来的“差不多”。
- 为了显得现代而降低对比度、可读性或操作确定性。

安全、干净、可用并不等于平庸。克制也应该有明确选择。

## 让主题可见

有意识地使用这些杠杆：

- 字体：展示字体/正文字体搭配、字号阶梯、字重、行长、数字样式。
- 颜色：主表面、强调色层级、语义状态、对比度。
- 空间：密度、区块节奏、卡片内边距、负空间、分组。
- 构图：网格、非对称、叠加、分栏、编辑流、受控密度。
- 表面：边框、阴影、层次、纹理、渐变、噪点、图案或刻意扁平。
- 动效：一个高影响瞬间或清晰状态过渡，避免到处都是零散动画。

每个界面至少应有一个产品特定记忆点。记忆点可以很小，但必须有意图。

## 让视觉服务产品

有辨识度不等于混乱。每个视觉选择至少应服务以下目标之一：

- 更快理解。
- 更强产品记忆点。
- 更清晰层级。
- 更明确可操作性。
- 更强操作信心。

如果某个视觉效果降低可读性、交互理解或状态感知，就删掉。

## 设计成功标准

完成设计或 review 前检查：

- UI 有命名的视觉方向。
- 方向符合产品目标和受众。
- 主题能在字体、颜色、空间、构图、表面或动效中看见。
- 主操作、次操作、危险操作和元信息层级清楚。
- 至少有一个产品特定记忆点。
- 它不是没有产品理由的通用 AI / SaaS 模板。
