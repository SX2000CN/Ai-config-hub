# 验证参考

报告前端工作完成前使用本参考。

## 命令验证

优先运行覆盖改动行为的最小命令：

- 类型化前端代码：typecheck。
- 代码风格和明显错误：lint。
- 组件逻辑：单元测试或组件测试。
- 打包和路由错误：build。
- 项目使用 Storybook 或视觉测试时，按项目约定运行。

不要跳过失败检查。应修复根因，或明确报告阻塞。

## 浏览器验证

涉及 UI 修改时，能运行应用就打开浏览器检查目标界面。

检查：

- 目标路由能渲染。
- 没有由本次改动导致的控制台错误。
- 桌面布局。
- 移动端布局。
- 相关 hover、focus、disabled、loading、empty、error 状态。
- 文本换行和长内容行为。
- 主操作路径。

如果无法做浏览器验证，说明原因并列出替代检查。

## 截图或视觉 review

有截图时检查：

- 截图视口和裁切。
- 是否文字重叠。
- 对比度和可读性。
- 对齐和间距节奏。
- 视觉主题是否可见。

## 最终证据

报告精确命令和结果：

```text
命令：<command>
结果：通过 / 失败 / 未运行
说明：<简短原因或阻塞>
```

只跑了代码检查时，不要声称已经视觉验证。
