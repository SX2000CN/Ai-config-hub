# 思维扩展简报模板

优先使用短格式。

```markdown
我建议先从 <推荐方向> 入手。

- 方案发散：<1-2 个替代方案，以及为什么不优先它们>
- 失败模式：<最可能失败的假设或边界>
- 简化路径：<能删掉或暂缓的复杂度>
- 维护者视角：<后续人类/AI 接手时最需要清楚的点>

下一步最小动作：<一个动作>
```

如果任务很小，直接返回：

```markdown
这个任务不值得启用思维扩展；按最小改动直接处理即可。
```

如果信息不足，最多问一个问题：

```markdown
进入实现前只需要确认一个点：<问题>。如果默认按 <假设> 处理，我建议 <方向>。
```
