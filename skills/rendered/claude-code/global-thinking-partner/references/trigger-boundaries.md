# 触发和边界

## 应触发

- 用户明确要求扩展思路、比较方案、挑战当前想法。
- 任务会改变架构、规则、自动化流程、同步流程或长期文档结构。
- 方案有明显分叉，且不同路径的风险和成本不同。
- 当前讨论出现“做不做”“有没有必要”“怎么设计更好”这类问题。
- 用户担心 agent 做出来的结果不完整、不够稳或过度偏离预期。

## 不应触发

- 单行修复、拼写修正、格式化、注释调整。
- 用户已经要求直接执行明确命令。
- 缺陷修复已经定位根因且只需要最小改动。
- 触发后只会重复已有工作状态系统、验证系统或提交流程。

## 权限边界

本 skill 默认只做推理和建议。

允许：

- 读取当前任务相关文件。
- 总结可选方案和风险。
- 提出最小下一步。

不允许，除非用户明确转入实现：

- 编辑文件。
- 运行会改变状态的命令。
- 创建、删除、同步、提交或推送。
- 把建议伪装成已经批准的计划。

## 与其他机制的边界

- 工作状态系统负责记录当前进度和接手信息，本 skill 不重复做状态日志。
- code review 负责检查已发生的 diff，本 skill 主要用于动手前或方向不确定时。
- frontend design 负责 UI 视觉和产品界面，本 skill 只负责更通用的思维扩展。
- verification 负责完成前验证，本 skill 只提示哪些验证点可能关键。
