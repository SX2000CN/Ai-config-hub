# CURRENT.md 健康检查与修复

当用户说「更新项目 AI 配置」「修复项目 AI 配置」「audit/repair 项目中枢」时，必须检查并修复 `.Ai-config/CURRENT.md`，不要只追加新状态。每次更新 CURRENT 或切换/结束任务前，也应先做本文的 hygiene，再写入本轮变化。

## 形态约束（软上限）

- 整文件不超过约 120 行或 6KB。
- 活跃任务最多 3 条，每条最多约 4 行，且必须带任务卡指针。
- 待确认、暂停/阻塞各最多 5 条，且必须带日期。
- 最近关闭最多 5 条，每条一行。
- 详情只写在 `tasks/*.md` 或正式文档；CURRENT 只保留指针、状态和最小下一步。
- 禁止写入：完整启动命令、环境拓扑长文、BuildId/SHA 账本、验收日志正文、技术栈百科、changelog 正文；最多一行链接到正确文档或任务卡。

## 检查项

1. 文件是否明显超过约 120 行 / 6KB。
2. 是否包含禁区内容：启动 runbook、环境拓扑长文、SHA/BuildId 账本、验收日志、技术栈百科、changelog 正文。
3. 活跃任务是否超过 3 条，或单条超过约 4 行且缺少任务卡指针。
4. 待确认是否缺日期、是否超过 5 条、是否超过 14 天无人跟进。
5. 最近关闭是否超过 5 条。
6. 任务卡已关闭/已废弃，但 CURRENT 仍列在活跃或待确认。
7. 是否把应在 README/ops/任务卡的内容复制进了 CURRENT。

## 修复顺序

1. 识别每条活跃/待确认对应的任务卡；没有任务卡的长文先压成一行指针，必要时补建任务卡承载详情。
2. 已完成且用户已确认的项：关任务卡（若适用）并从 CURRENT 移到最近关闭一行摘要。
3. 超龄待确认（默认 14 天，项目模板另有约定从其约定）：催用户，或标「未跟进关闭」滚到最近关闭。
4. 禁区正文：删除 CURRENT 中的复述，改为指向已有文档/任务卡；若唯一信息只在 CURRENT，先迁到正确文件再删复述。
5. 截断最近关闭到 5 条。
6. 关闭任务卡后同步从 CURRENT 的活跃/待确认/暂停区移除对应行。
7. 重写 CURRENT 为薄仪表盘：接手导航 + 活跃 + 待确认 + 暂停阻塞 + 最近关闭 + 形态约束。
8. 自检上限；仍超限则继续外迁，不靠缩小字体式压缩糊弄。

## 不做

- 不把 hygiene 做成自动 LLM 摘要黑盒而不落任务卡。
- 不删除任务卡正文来「变短」；短的是 CURRENT，不是历史事实。
- 不在只读问答时强行改写 CURRENT。
