# 可访问性参考

表单、弹窗、菜单、导航、仪表盘、交互组件和会改变状态的 UI 使用本参考。

## 语义

- 动作用 button，导航用 link。
- 能用原生控件时优先用原生控件。
- 保持标题层级合理。
- 列表、表格、landmark 和表单元素应在语义匹配时使用。

## 键盘

交互 UI 必须能不用鼠标操作：

- 焦点顺序符合视觉/逻辑顺序。
- 焦点可见。
- 弹窗和浮层优先使用项目已有可访问性 primitives。
- Escape、Enter、Space、方向键和 Tab 行为符合组件类型预期。

## 表单

- 输入项有可见 label 或 accessible name。
- 必填项清晰。
- 错误靠近字段，并在技术栈支持时与字段关联。
- 帮助文本和约束尽量在提交前可见。
- 不明显的禁用状态应说明原因。

## 颜色和对比度

- 颜色不是唯一状态提示。
- 弱化文字仍然可读。
- 焦点环和错误状态有足够对比。
- 玻璃、渐变和图片背景不能牺牲文字可读性。

## 动效

- 用动效解释过渡或状态变化。
- 避免阻碍理解的动效。
- 明显动画应尊重 reduced motion 偏好。

## 状态播报

动态 UI 需要考虑是否播报状态变化：

- 保存成功或失败。
- 异步加载完成。
- 校验总结。
- toast 和 alert。

如果项目已有可访问性 primitives，优先复用。
