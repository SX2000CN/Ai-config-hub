# 脉络工作流

目标：在代码或工作流关系复杂时，先利用当前可查询的结构化事实源建立上下文，再读取必要文件和做验证。不要让它变成每个任务的新仪式。

## 1. 判断是否触发

满足下列任一项，且结构化事实源能明显减少搜索成本时使用：

- 用户问调用链、影响面、模块关系、复杂配置关系或项目结构。
- 任务涉及跨模块改动、重构、接口变化、复杂 bug 定位或测试选择。
- 非代码工作流有多对象、多状态、多依赖，例如发布、配置治理、设计流程、多人 / 多 AI 接手。
- 大范围 `rg` / `read` 会明显增加上下文负担，且存在更结构化的事实源。

不满足时回到普通工作流。简单问答和明确局部任务不因为本 skill 存在而初始化索引、创建任务卡或扩展计划。明确文件的小修、纯 Markdown / 任务卡状态分析、一次精准搜索能解决的问题，不使用本 skill。

本 skill 不自动拉起 `project-ai-config-hub`、思维伙伴或任务卡更新流程；如果任务跨域，回到主任务路由判断主次关系。

## 2. 选择事实源

- 代码结构关系：如果当前会话暴露 `context_thread_*` MCP 工具，且项目已有索引，优先用 context-thread。
- 非代码工作流关系：优先读 `.Ai-config/CURRENT.md`、相关任务卡、skills registry 和近邻规则文档。
- 没有结构化事实源：直接使用 `rg`、文件读取和项目已有验证，不停下来要求用户安装或初始化。

context-thread MCP 可用时，先用 `context_thread_status` 判断索引是否可用。若提示未初始化：

- 简单问答和局部任务：直接回退到 `rg` / 文件读取。
- 跨模块关系、长期项目理解或持续接手任务：说明初始化会生成项目本地索引，征得确认后再按全局规则里的 CLI 调用契约执行 init（`context-thread` 不是可直接执行的裸命令，需要用 `node` 加真实入口路径，或目标项目自带的 wrapper 脚本，具体路径见 `~/.claude/CLAUDE.md` / `~/.codex/AGENTS.md` 的 Claude Code / Codex 专用补充）。

若 `context_thread_status` 提示存在 pending changes，说明索引落后于当前文件状态：

- 能手动刷新且任务确实依赖关系判断时，按同一套 CLI 调用契约运行 sync（同样优先用目标项目提供的 wrapper，没有 wrapper 时用 node 加真实入口路径）。
- 不能刷新时，仍可用索引缩小范围，但最终判断必须读取当前文件确认。
- 刚修改文件后，不要立刻把索引结果当成最新事实。

索引自动更新只在 MCP server 已运行、项目已初始化、文件 watcher 可用且变更文件类型受支持时成立。MCP 没启动、watcher 被禁用或平台不支持时，不会自动同步；这不是失败，小任务直接回退，大任务按需手动 sync。

## 3. 代码任务工具选择

context-thread MCP 可用时，工具选择和常见用法链路已在 MCP server 自带指南里说明（`context_thread_status` 可确认 server 是否在线）。这里只补充两条不在 server 指南里的规则：

- 刚修改文件后，不要立刻依赖索引判断最终事实；watcher debounce 约 2 秒，修改后的关系要等下一轮同步才反映。
- 只在需要确认真实文本、最新修改、配置细节、测试内容或文档语义时再读文件；其他情况优先用 context-thread 减少文件读取。

## 4. 非代码任务关系索引

如果任务会跨会话、跨工具、等待确认或需要接手，并且关系复杂，可以在任务卡中加入简短 `关系索引`。它只记录当前必须接手的结构关系，不写成长篇总结。

不要为了临时讨论、一次性问答或一轮内完成的小任务创建关系索引。

## 5. 输出边界

回答或交接时区分：

- 已由结构化事实源确认的关系。
- 读取文件或运行验证确认的事实。
- 基于当前信息做出的推断。

context-thread 提供 code context，不提供产品需求；`.Ai-config` 提供工作状态，不替代用户当前说明。
