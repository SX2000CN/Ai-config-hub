# 思维伙伴工作流

目标：在动手前或方案不确定时，用短、准、低副作用的方式扩展思考，而不是替代主工作流执行任务。

## 1. 判断是否值得触发

只有满足下列至少一项时才使用：

- 任务有多个可行方案，且选择会影响后续维护。
- 用户要求“先分析”“扩展思路”“看看有没有更好做法”。
- 当前方案依赖未明说的假设。
- 任务涉及架构、重构、规则、自动化、权限、同步、迁移、状态机或长期文档。
- agent 可能过早收敛到第一个实现路径。

不满足时，直接返回主工作流，不要增加噪音。

## 2. 固定四个镜头

按需选择 2-4 个镜头，不必每次全用：

1. 方案发散：还有哪些路径？最小改动、稳健方案、长期方案分别是什么？
2. 失败模式：这个方案在哪些边界、假设或未来变化下会失败？
3. 简化路径：能否用更少概念、更少文件、更少自动化完成？
4. 维护者视角：后续人类或 AI 接手时，命名、边界、文档和验证是否清楚？

## 3. 输出约束

默认输出 3-5 条，不写长篇论文。

每条建议应包含：

- 观察：发现了什么问题或机会。
- 影响：为什么值得在当前任务中考虑。
- 建议：下一步最小动作。

避免：

- 泛泛的“加强测试”“注意安全”。
- 没有当前项目语境的抽象建议。
- 把建议写成已决定的计划。
- 在用户未确认前要求大范围重构。

## 4. 低副作用边界

默认不修改文件，不运行会改变状态的命令，不创建提交，不同步全局目录。

如果确实需要读取项目文件来理解上下文，只读即可，并在输出中说明依据来自哪些文件。

如果用户明确要求进入实现阶段，应退出本 skill 的思维扩展模式，转入正常计划和实现流程。

## 5. 结束条件

输出应以一个推荐方向收束：

- “推荐先走最小方案，因为……”
- “推荐先补一个验证点，因为……”
- “推荐暂不新增抽象，因为……”
- “推荐进入实现前先确认一个问题：……”

不要留下过多开放分支。
